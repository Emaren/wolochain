Financial timer containment: exact four-unit scope, no funds

The controller never changes website/validator units, databases, HBA, wallets
or route code. Persistent high-priority systemd control masks preserve all
original fragments/drop-ins in place. Root-private copies and exact enable-link
preimages precede unit changes. Protected process/listener identities are checked.

Run only /usr/bin/python3 -I against an exact reviewed, root-owned staged source.
inspect is read-only. A canonical manifest must be staged root-only. request
creates a fresh five-minute unsigned payload; it grants no authority.

The existing owner personally inspects/signs that payload locally with
financial_timer_owner_signature_v1.swift. It uses the already enrolled C08
Keychain identity, a NEW timer-only domain, exact source/manifest/host binding,
and zero funding. Existing C01/C08 signatures cannot substitute. Never run its
sign mode as an agent or export a private key. Transfer only the signed permit.

apply requires the signed action to equal --action. QUARANTINE stops, disables
only the recorded four-unit links, and masks both timers and services. Manual
start negatives run only after every mask is effective. Nonces are consumed
durably before unit work. Partial failures retain/reestablish denial, never
resume. RECOVER requires a NEW signed nonce and completes denial after an
interrupted operation; it tolerates already removed original enable links.

RESTORE is a DIFFERENT authorization. It additionally requires an independently
admitted root-only financial resume receipt, whose digest the owner signs.
That receipt must bind this host/machine/original-manifest, current expiry,
independent_financial_resume_authorized=true, and actual accepted legacy HTTP
writer exclusion. This controller never creates that admission. Resume is NOT
authorized today. Trigger/start history and elapsed schedules are irreversible.
Inverse errors re-quarantine; any in-flight legacy HTTP work requires separate
reconciliation. Restoring bytes cannot reverse a financial effect.

This contains two automatic paths only. It does not fence arbitrary HTTP POST,
direct SQL owners, other producers, or close C03. Live unit changes require a
separately accepted exact source and fresh owner/Central timer authorization.
